# Stage 1 demo deployment

The public GitHub Pages artifact is built from `main` or `stage-1-integration` by `.github/workflows/pages.yml`. Run `npm run verify:deploy` locally to build and reject unexpected files in `dist`. The repository path is `/RejseFlex/`; the manifest and service worker use this scope. Navigation fetches the current page online and uses the cached shell offline. Personal plans and later documents stay in browser IndexedDB and are never part of `dist`.

Address autocomplete uses the public Komoot Photon demo endpoint behind `src/geocoding.js`. Search text is sent to Photon as the user types after a short debounce; requests are restricted to Denmark by `countrycode=DK`, and non-Danish results are discarded locally. It requires no browser API key, so the Pages build works immediately. The service is permitted for modest project traffic but has no uptime guarantee and can be throttled. Switch to a hosted plan or private instance before wider or reliability-sensitive use; see `docs/research/geocoder-autocomplete.md`. Map tile requests go to OpenStreetMap. Personal journeys and documents are not sent to Photon or Pages. The demo train times and unknown transport rules are not usable travel advice.

Manual verification on the published Pages URL: open `/RejseFlex/`, choose both addresses and manual stations, provider, date and desired departure/arrival time. Confirm the planner has no import button. Continue to information entry, enter clock times, check the live 15/30-minute assistance calculation, choose DSB/Rejsekort (or leave it unselected), upload synthetic PDF/DOCX documents and stage each booking confirmation independently. Save to the read-only overview; check quick document access, timeline order, missing-information summary and booking status. Reopen editing, replace/remove documents and verify cancellation and navigation back to planning preserve data. Reload and reopen the saved journey; open both documents again. Repeat at mobile width and test midnight dates. Verify the public shell references the current build asset, not a cached older bundle. Personal plans and documents must not appear in the public deployment artifact.

Install from a supported mobile browser and relaunch; test online/offline reload when changing PWA infrastructure. This redesign keeps the existing service worker and install scope.
